# Subscription approve — implementing with HTTP parity

`POST subscription/<uid>/approve` (`subscription_approve` in `BE/application/views/subscriptions_views.py`) is implemented in Go
(`BE_GO/internal/{domain,repository,service,handler}/subscription_approve.go`), sharing the reject/archive/delete prologue
([subscription-lifecycle](subscription-lifecycle.md)). Registry `association.members.update`. Its success path publishes a Celery
task through the [Celery producer](celery-producer.md); Django's workers execute it.

## Behaviour

- `@api_view(['POST'])`: `Allow: POST, OPTIONS`; OPTIONS names `Subscription Approve` (no docstring).
- `is_valid_uuid` first (400 list), then `scoped_queryset(SportAssociation.objects).get(user=request.user)` (athletes and owners
  without an association: the 500 page), then the group-aware `Subscription.objects` row (`X-Group-Id`; soft-deleted rows are
  found; limited to the association under an association impersonation): a miss is `404 {'msg': 'Subscription not found.'}`,
  another association's row a DRF 403 `User not allowed.`, an accepted row a DRF 403
  `User cannot change the status of the subscription.`.
- Otherwise `status_flag=4` and `acceptance_date=timezone.now()`: the DateField stores the UTC date, auditlog renders the in-memory
  datetime (`str(datetime)`, e.g. `2026-11-09 10:00:00.000500+00:00`), so `acceptance_date` is always in the entry.
- A row without a signature (`has_signature`: a non-empty key or URL) takes `signature_storage_key` and `signature_url` from the
  newest (`-creation_date`) other ACCEPTED/PENDING row of `scoped_queryset(Subscription.objects)` with the same associate
  (`associate=None` matches rows without an associate) and either column not null, only when that row `has_signature` (a newest
  candidate with an empty key copies nothing). The lookup follows `X-Group-Id` and finds soft-deleted rows.
- `Subscription.save()` fills missing dates from the owner's settings; the changed fields are audited, indexed `direct`.
- `subscription_approved` -> `check_workflows_trigger.delay(trigger_type='subscription_approved',
  sport_association_id=UUID(<association>), subscription_id=UUID(<subscription>))`, right after the autocommitted save. Response
  `{'data': {'msg': 'subscription approved.'}}`.

## Go implementation

One transaction for the lookups and the save, committed, then the publish with `context.WithoutCancel` and a 10 s bound (Django's
view is not interrupted by a client disconnect). A publish failure after the retries is the 500 page with the approval kept, as in
Django. `service/subscription_approve_test.go` pins the order (save, commit, publish), that nothing is published without a commit,
and that cancelling the request after the commit still publishes.

## Not ported

Nothing on this route is refused. The task's execution (workflow triggers) stays in Django.
