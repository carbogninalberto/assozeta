# Subscription tax code, import status, federation list, gym token links and document delete — implementing with HTTP parity

`POST subscription/calculate-tax-code`, `GET subscription/import/status`, `GET subscription/get-associations-for-federation`, `POST subscription/generate-token-link`, `GET subscription/validate-token-link-and-get-subscriptions` and `DELETE subscription/<uid>/delete-document/<subscription_file_id>` (function views in `BE/application/views/subscriptions_views.py`) are implemented in Go (`BE_GO/internal/{domain,repository,service,handler}/subscription_misc.go`, the codice fiscale in `BE_GO/internal/codicefiscale`). Registry: `association.members.read` (calculate-tax-code, import/status), `association.members.update` (delete-document); the federation list and both token-link routes are in `EXCLUDED_ENDPOINTS`. `Allow` is the decorated method plus OPTIONS; OPTIONS names come from the function names and the descriptions are empty.

## Behaviour

- **calculate-tax-code** has no permission class (DRF's `AllowAny`): anonymous requests and athletes are answered, the registry still applies to collaborators, and an owner-scoped athlete session is answered too.
  - A non-dict body is a 500 (`data.keys()`). Without one of `first_name`, `sex`, `last_name`, `born_date`, `born_city` the answer is 200 `{'tax_code': None}`.
  - `None` or `''` for a name, the date or the city, or a sex other than `m/M/f/F` is 400 `{'msg': 'alcuni dati sono mancanti.'}`, checked in the view's order (last name, first name, sex, date, city). A non-string sex reached by that check is a 500 (`upper()`).
  - `codicefiscale.encode(lastname, firstname, gender, birthdate, birthplace)` (python-codicefiscale 0.10.3): a birthplace it cannot map is 400 `{'msg': 'Città non mappata.'}`, every other exception 400 `{'msg': 'alcuni dati non sono validi.'}` (non-string values, impossible dates, a code whose own decode fails). encode decodes its result with the two-digit year read in the current century, so a 1920 birth in a municipality closed in 2015 is invalid while a 1950 one is not.
  - The Go port (`codicefiscale.Encode`) reproduces slugify (NFKD, text-unidecode, quote and dash rules), the consonant/vowel codes, dateutil's parsing of the date slug (yearfirst when the first part has four characters, else dayfirst; compact `YYYYMMDD` is year, day, month under dayfirst; two-digit years and missing parts from the current date), the municipality/country/code lookup with its date ranges and fallback, the CIN and the decode check. The lookup index is embedded from the library's data (`data.txt.gz`, regenerated by `tools/go-migration/codicefiscale_data.py`).
- **import/status** reads `request.user.sport_association`: athletes 403 `{'detail': 'User is not a sport association'}`, an owner without a live association 500. It answers `{'importing': doing}` of the association's newest importing status (`doing` may be `None`), `False` without one.
- **get-associations-for-federation** (same association lookup) lists the association's subscriptions whose custom_data text contains `"type_of_associate": "asd-o-ssd"` or `"type_of_associate": "scuola-asc"` (`UPPER(custom_data::text) LIKE UPPER(...)`, so key case and nesting do not matter). `Subscription.objects` is group-aware and keeps deleted rows; an association-scoped session narrows it. Each dict with a hashable `denomination` not seen before gives `{'id', 'denomination'}` in database order (the first of equal denominations wins); a non-dict custom_data or an unhashable denomination is skipped by the view's try/except.
- **generate-token-link**: a missing or `None` `gym_name` is 400 `{'error': 'gym_name is required'}` (before the association lookup, so also for athletes); then athletes 403 and owners without an association 500. A non-dict body is a 500. The link stores a uuid4 token, `str()` of the value (numbers, booleans and containers as Python renders them), the owner's association and `expires_at` two days ahead; it answers 201 with the token, the original value and the in-memory expiry. A NUL, a lone surrogate or more than 255 characters fail the insert (500, nothing stored). One auditlog create, indexed directly; the view's second `save()` changes nothing.
- **validate-token-link-and-get-subscriptions** has no permission classes (anonymous requests are answered; the admin session rule still applies).
  - `is_valid_uuid(token)`: no token is 400 `["one of the hex, bytes, bytes_le, fields, or int arguments must be given"]`, a malformed one the usual list. The last `token` parameter is used.
  - The link is `filter(token=<raw text>, expires_at__gt=now).first()`; every expired link is then deleted (auditlog deletes indexed from `changes_json.sport_association`, by the request's user or anonymously). Without a link the answer is `{'expired': True}`.
  - A link without a gym name is a 500 after the deletions. Otherwise the associates with an active (`current_year() == 'corrente'`) accepted or pending subscription ending today or later are excluded, and the candidates are the link association's subscriptions whose custom_data text contains the first three characters of the gym name (all of it when it is three or shorter) and that started at least 180 days ago, rows without associate included. A non-dict custom_data, or a non-string `school_name` (or `denomination` when there is no school name), is a 500.
  - A candidate matches when fuzzywuzzy's `fuzz.ratio` (difflib's SequenceMatcher, Python `str.lower()`) of the two names is above 70. The matches are rendered with SubscriptionSerializer (the subscription-reads port; an empty payments sum is the integer 0), and `default_custom_data` comes from the first match with a `school_name`.
- **delete-document**:
  - `is_valid_uuid` on both ids (400 list), then `scoped_queryset(SportAssociation.objects).filter(user=request.user).first()`: none (athletes, owners without a live association) is 403 `{'detail': 'User not allowed.'}`. An owner-scoped athlete session gets the scoped-request 403 first.
  - The association's group-aware, scoped subscription and then its file (`filter(pk, subscription)`); either missing is a TypeError, 500.
  - Outside an association-scoped impersonation, a Document no other row references is deleted with `subscription_file.document.delete()` and, through the cascade, the file; `subscription_file.delete()` on the view's stale instance then records one more auditlog delete of the file. When another row (a file of any subscription, or any other reference to the Document) still points at the Document, only the caller's file is deleted: the Document, its stored file and the other links stay. Inside an association-scoped impersonation only the file is deleted. Entries are indexed to the actor's own association (`actor.sport_association`), or not indexed when the actor has none.
- Requests are not atomic: the expired-link deletions stay when validate-token-link fails afterwards, and generate-token-link's link stays when rendering the response fails.

## Not ported

- `subscription/associates-draft/list/approve`: every successful draft goes through `create_subscription` (users, associates, subscriptions, payments, documents, emails). It stays on Django (see `associates-draft.md`).
- calculate-tax-code inputs outside the ported subset are refused with a 500 (no write happens either way): characters whose NFKD form leaves the embedded transliteration ranges (U+0001-U+052F, U+1E00-U+1EFF, U+2000-U+206F, U+20A0-U+20CF; astral characters are dropped as in text-unidecode), lone surrogates, HTML entity or numeric character references, runs of more than 30 combining marks, and date slugs containing letters (month names, ISO `T` times). The port covers every date written with digits and separators. If the `Unidecode` package were installed next to python-slugify, Django would transliterate differently.
- validate-token-link through the paired server: an `expires_at` whose instant lies outside years 1..9999. Go answers 500 (the expired links are already deleted, as in Django).
- generate-token-link with an uploaded file as `gym_name` (multipart): 500 before any write.

### API v2: unknown link tokens while a pairing is active (v2-misc-3)

`instance.sso.public_links.source_token` (`service/bakney_public_links.go`): only canonical UUIDs are asked. In one
transaction the first pairing is locked with its configuration; a self-hosted instance whose pairing is pending or paired, has a
remote pairing id and still matches the settings (`check_binding`), a live paired association with an active association user
(and, for a card, a subscription of that association) lead to `POST <BAKNEY_SSO_API_BASE>/pairing/v1/public-token` with the kind,
the token, the resource id, the remote pairing id and the pairing secret. The answer is used when it carries the protocol
version, the pairing's binding (instance, pairing, association, origin, callback), the kind, a canonical generation and an aware
`expires_at` in the future (plus the same resource id for a card, a string `gym_name` of at most 255 characters for a link);
the capability is never stored. Any other answer, status or failure means the token is unknown. validate-token-link deletes the expired links first, then asks, and continues with the paired association
and the answered gym name.

157 cases (14 new, same stub and checks as `misc-routes.md`): a vouched token (paired; pending with a group header), 401, 500, a
card answer, a missing, numeric or 256-character gym name, an expired grant, another association in the answer, and the lookups
that ask nothing (upper-case token, disconnected pairing, an instance that is not self-hosted, a stored token).

- RED (`v2misc3-red-r1`): Django 157/157; Go 500 on `subscription-misc-validate-paired-server-vouches`.
- GREEN (`v2misc3-final-r1`, after the last base merge; first `v2misc3-versioned-r1`): 157/157 on native Django, native Go, Caddy `/api/v1` and `/api/v2`.
- Mutation (`v2misc3-mutation-r1`): a gym name limit of 256 fails Go on
  `subscription-misc-validate-paired-server-gym-name-too-long` (CAUGHT).

- Shared document (later change): the cases of one document under two files now expect the caller's link removed with the Document kept, then a repeat (500), then the last link taking the Document with it. Replaces the v2-rest-c cascade cases.
