# Web UI API version (beta switch)

The self-hosted web interface can call the Go API (`/api/v2`) instead of Django
(`/api`). Caddy already routes `/api` and `/api/v1` to Django and `/api/v2` to
Go; this switch only changes which prefix the browser uses. Both stay served,
so the rollback is switching the setting off.

## Setting

`InstanceConfiguration.ui_api_version` (`v1` default, `v2`), added by Django
migration `instance.0009_ui_api_version` (Django owns the schema).

- Public `GET instance/config` exposes it as `features.uiApiVersion`.
- The owner admin `PUT instance/admin` accepts `uiApiVersion` next to `oem`
  (`InstanceAdminSerializer`, a `ChoiceField` with source `ui_api_version`).
  The body keys must be a non-empty subset of `{'oem', 'uiApiVersion'}`;
  otherwise the existing 400 `["Only instance branding can be edited here."]`.
  Errors use DRF's shapes: `"<str(value)>" is not a valid choice.`,
  `This field may not be null.`, and both keys' errors together.
- A changed value writes one auditlog UPDATE entry on the configuration,
  `{'ui_api_version': [previous, new]}` with `additional_data
  {'actor_id': <authenticated actor>}` (the same entry shape as the backup
  actions) and its AuditLogIndex row. An unchanged value saves without one.
- No route or `urls.py` changes.

Go returns and accepts the same: `dto.InstanceAdminKeysWithin`,
`dto.InstanceAdminEdit`, `repository.InstanceAdmin.AppendUIAPIVersionChange`
(reuses `AppendBackupAction`), the bootstrap SQL and `InstanceFeatures`. Go's
instance setup inserts `ui_api_version = 'v1'` (the model default).

## Browser

`UI/src/utils/apiVersion.js` keeps the active host for the session. The
fetch/XHR overrides in `ApiMiddleware.js` rewrite same-origin `/api/...` URLs to
`/api/v2/...` while v2 is active; download links and iframes use
`rewriteApiUrl` too. v2 is activated only after `GET /api/v2/readyz` succeeds
(cached per session); a network error or 5xx on the bootstrap requests returns
the session to `/api`. A per-browser override `?api=v1|v2` (localStorage
`assozeta_api_override`, `?api=auto` clears it) wins over the instance setting.
A non-default build-time `__bakney.env.HOST` disables the switch.

- A browser without a cached instance setting (first visit, or right after a
  login, which clears localStorage) reads `instance/status` and
  `instance/config` from `/api`, then switches; later loads use the cached
  setting. The override is mirrored in sessionStorage so login/logout keep it.
- The app's `fetch-intercept` wrapper passes every call as a `Request`; a
  rewritten `Request` is rebuilt from its buffered body
  (`rewriteFetchInput`), because copying the body stream makes Chromium send a
  streaming upload, which fails on HTTP/1.1 (`ERR_ALPN_NEGOTIATION_FAILED`).
- Requests the UI can send that Go still refuses on v2 are listed in
  `v2-refusals.md` (the dashboard widgets `todaylessons` and
  `expiredPayments` are now ported).

## Evidence

- `instance-admin` family: 164 cases (23 new for the version), generated by
  `TESTS/fixtures/generate_instance_admin_http.py`; the adapter now checks the
  audit entry and index row of every case. RED: Django 164/164, Go fails
  (`owner-admin`, missing `features.uiApiVersion`). GREEN `versioned-g1`:
  164/164 on native Django, native Go, Caddy `/api/v1` and `/api/v2`. Mutation
  (audit written only for an unchanged value): CAUGHT on `ui-version-enable`.
- `instance-bootstrap`: 129 cases (new `configured-config-ui-api-v2`). Django
  129/129; Go RED on `configured-config`, then 129/129 with the repository
  integration groups. Mutation (feature fixed to `v1`): caught.
- Re-run on shared Go code: `instance-setup` 86/86 and `instance-outbound` 106/106 (native Django and Go).
- Browser (`TESTS/adapters/django/ui_api_version_browser.py` with
  `TESTS/browser/ui-api-version.mjs`): the built UI behind the shipped
  Caddyfile, real Django and Go servers on one PostgreSQL/Redis, password
  login. v1: all API calls on `/api`; the owner enables v2 on the Self Instance
  page; the same and a new browser then call only `/api/v2` (an independent
  observer on Django sees no API request, except the first-visit bootstrap
  reads); `?api=v1` and a failing `/api/v2/readyz` keep `/api` without error
  dialogs; switching off returns to `/api`. Two audit entries
  `[v1, v2]`, `[v2, v1]`. Not covered in the browser: file downloads/uploads,
  manual assets and impersonation (routed through the same rewrite, unit
  tested only).
